# First run as a user sees it: runnable commands, a clean check after new

## Context

0.1.2 was installed from npm into a real project (glivo-web, a Next.js app on Bun) with an
empty npm cache, following the README as a new user would: `npx honestdocs init --agents`,
`new`, `brief`, `rules`, `search`, `check`, then commits with the trailer, `index`, `done`
in a throwaway clone. The method held up; two things a first-time user meets did not:

1. **Every command honestdocs prints or writes is a bare `honestdocs …`.** After
   `npx honestdocs init` there is no such command — PowerShell answered "not recognized".
   The `init` hints, 8 lines in the AGENTS.md section, 5 in the skill, the documents
   folder's README and every "run `honestdocs index`" in `check` all send people and
   agents to it. An agent following AGENTS.md fails on its first step, `honestdocs brief`.
2. **`check` fails straight after `new`**: `progress` "" should be "0/1", and INDEX.md
   stale. `done` reruns the index; `new` did not.

## Goals / Non-goals

Goals: every command honestdocs tells someone to run works in the project as it was set
up; `init`, `new`, `check` in that order is green.

Non-goals: detecting every package manager. `--help` usage lines keep the program's name
(`honestdocs check [--fix]`), as every CLI's do.

## Decision

- A `command` key in the config — how this project runs honestdocs. `init` writes it from
  the runner that started it (`npm_config_user_agent`): `bunx honestdocs` under Bun,
  `pnpm dlx honestdocs` under pnpm, `npx honestdocs` otherwise — never a bare
  `honestdocs`, which only exists after a global install on one machine. A config without
  it means `npx honestdocs`.
- The guide texts (agents section, skill, docs README, the first rule, the method) take
  `{{command}}`; every message that tells someone to run something uses `config.command`.
- `new` writes the new document's `progress` and regenerates INDEX.md — without the git
  pass `index` makes, so starting a document stays instant in a large repository.

## Alternatives considered

- **Hard-code `npx honestdocs` everywhere.** Simplest, and works wherever Node is. Rejected
  as the only answer: a Bun project's agents would be sent through npm, and a team that
  runs it another way has no way to say so. It stays the default.
- **Detect the runner on every run instead of storing it.** The text in AGENTS.md is
  written once and read by everyone; it has to be stable, not depend on who last ran
  `init --agents`.
- **Tell users to install globally.** Pushes a step onto every teammate and every CI
  runner, and pins nobody to a version.
- **`new` runs the full `index`.** Correct, but on Glivo's 259 documents that is ~3 s of
  git for a command that only adds one file.

## Checklist

- [x] `command` in the config: written by `init` from the runner, defaulting to `npx honestdocs`
- [x] Guide texts and every printed "run …" use it; `--help` usage lines unchanged
- [x] `new` leaves `check` green
- [x] Tests: Bun runner, default runner, no bare command in what `init` writes, `check` after `new`
- [x] README and CHANGELOG
- [ ] Rerun the glivo-web walk-through on the published version

## Verification

```sh
node --test
node bin/honestdocs.mjs index && node bin/honestdocs.mjs check
```

Then the published package, from an empty npm cache, in a copy of a real project:
`npx honestdocs init --agents && npx honestdocs new … && npx honestdocs check`.
